# SushiCTF プロジェクト知識

## 現在の状態

- 企画段階
- TryHackMeで一般公開できるRoomとして完成させることが目標
- 想定難易度はTryHackMe初級〜中級
- 実装方式、配布マシン、具体的な脆弱性は未決定

## 制作目標

物語を調査しながら進める初心者向けCTFを制作する。技術的な攻略と事件調査を分離せず、攻略によって得た証拠を読み、人物関係や真相を回答する体験を中心にする。

## TryHackMe Room方針

Roomを探偵事務所の調査ノートとして構成する。

- Room導入文：所長からアルバイトへの依頼書
- 各Task：調査ノートの章または調査日
- Task本文：所長の指示、主人公のメモ、判明した証拠
- Question：ノートに残された空欄
- Answer：人物名、場所、目的、判明した真相
- Hint：所長からの助言や付箋
- 最終Task：調査報告書の完成

初心者が次に調べる対象を理解できる導線を置く。技術を覚えることが、そのまま事件の進展になる構成を目指す。

公開を考慮して以下を満たす。

- Answerは表記揺れの少ない英数字を基本とする。
- 固有名詞のローマ字表記を確定する。
- 日本固有の制度、沖ノ鳥島、EEZには、理解に必要な最小限の説明を添える。
- プレイヤー向けテキストをコードへ散在させず、将来英語化できる形で管理する。
- すべてのAnswerに確認可能な証拠を用意する。
- マシン再起動後も同じ手順で攻略可能にする。
- 外部サービスに依存させない。
- 意図しない攻略経路や壊れやすい状態を公開前に検証する。

## 想定攻略フロー

一本道に近い構成を基本とする。

1. 対象IPと最初の調査目的を受け取る。
2. 公開Webサイトを調べる。
3. 隠しページやバックアップから内部情報を得る。
4. 漏洩認証情報または初歩的なWeb脆弱性から内部へ進む。
5. サーバーへ侵入して業務ファイルを調べる。
6. 基本的なLinux権限昇格を行い、最終証拠へ到達する。
7. 調査ノートの最終回答を提出する。

## 想定技術要素

- ポートスキャンとサービス列挙
- `robots.txt`、HTMLコメント、隠しディレクトリ
- 公開バックアップや設定ファイルからの情報収集
- 初歩的な認証突破またはWeb脆弱性
- SSHによる初期侵入
- 内部ファイルの調査
- cron、sudo設定、SUIDなどによる基本的なLinux権限昇格

総当たり、偶然、外部サイト、壊れやすいタイミングに依存させない。重要な手がかりには必要に応じて段階的なHintや別経路を用意する。

## 未決定事項

- 使用するWeb脆弱性
- Linux権限昇格の方式
- マシン構成とビルド方式
- Task分割、Question数、Hint構成
- Flag回答の正規化ルール
- 日本語版と英語版の制作順序
- Roomの難易度、推定所要時間、前提知識

## 優先順位

1. 初心者が詰まりにくいこと
2. 攻略の進展と物語の進展が一致すること
3. すべての回答を証拠から導けること
4. TryHackMe上で安定して再現・公開できること
5. CTF環境外への攻撃を必要としないこと
