# 「御厨こども食堂の謎」オンライン版 要件

更新日：2026-10-28

状態：基本的な利用仕様を整理済み。技術構成・費用・運用設計は検討中。オンライン版は未実装。

## 目的

プレイヤーがアカウントを登録し、ブラウザから調査ノートとKali Linuxの調査端末を利用できるようにする。プレイヤー自身によるDockerの導入やネットワーク設定を不要にする。

## 想定する運用規模

- 初期の同時プレイ人数は5人程度を需要予測の参考値として扱う（2026-10-28時点の概算）。
- 月額の運営費は希望1,000円以内、上限2,000円とする（2026-10-28確定）。
- 費用の監視・制御はAWS側の設定で行う（2026-10-28確定）。

## クラウドの選定状況

- AWSを前提に設計を進める（2026-10-28）。
- リージョンは東京を仮案とし、利用時だけ調査環境を起動する構成を検討する。VMの性能、調査ノート・DBの配置、総費用は未確定。

### AWS側の予算制御

予算制御が発動したら、新規調査環境の起動を停止し、プレイ中を含む稼働中の調査環境も強制終了する。調査ノートの進捗・回答・調査メモは保持する（2026-10-28確定）。

費用制御の具体的な方法は以下を設計案とする。

- AWS Budgetsで月額費用を監視し、予算への接近を運営者へ通知する。
- Budgets ActionsでVM起動用のIAMロールに拒否ポリシーを適用し、新規VMの作成・起動を制限する。参照：[Budgets Actions](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-controls.html)。
- 強制終了の具体的な方法、動的に作成される環境の終了対象を管理する方法、発動する金額、翌月の解除方法は未決定。

AWS Budgetsには請求データ反映の遅延があり、情報の更新は1日最大3回、通常8〜12時間間隔である。通知・アクションの発動前に設定額を超える可能性があるため、月額2,000円を厳密に保証する仕組みとしては扱えない。参照：[更新頻度と遅延](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html)。

## トップページ・アカウント

| ID | 要件 |
| --- | --- |
| TOP-01 | ユーザーはユーザーID・パスワードでアカウント登録できる。登録時に収集する情報はこの2項目のみとする。 |
| TOP-02 | ユーザーはユーザーID・パスワードでログインできる。 |
| TOP-03 | ユーザーはログアウトできる。明示的なログアウト時はセッションを無効化し、接続済みの調査端末との接続を切り、調査環境を終了する。 |
| TOP-04 | ログインしたユーザーは自分の調査ノートにアクセスできる。 |
| TOP-05 | ログインしたユーザーは自分の調査用VMを起動できる。 |
| TOP-06 | ユーザーは他のユーザーの調査ノートを閲覧・変更できない。 |
| TOP-07 | アカウント登録時とVM起動時にCloudflare TurnstileでBot検証し、サーバー側のSiteverify検証が成功した操作を受け付ける。 |
| TOP-08 | パスワードを忘れたユーザーは、新しいIDでアカウント登録し、進捗・回答・調査メモが初期状態のノートで最初から開始する。 |
| TOP-09 | アカウント登録・ログイン・VM起動にサーバー側の回数制限を設け、自動化された大量試行や連続起動を抑制する。 |

### Bot対策とパスワード紛失時の扱い

以下は確定した方針（2026-10-28）。

- ID・パスワードで登録・ログインし、パスワード紛失時は新しいIDで最初から開始する。
- 登録時とVM起動時にCloudflare Turnstileを利用する。無料プランで単独利用でき、AWS上のアプリにも組み込める。サーバー側でSiteverifyを実行し、検証が成功した操作を受け付ける。参照：[料金・単独利用](https://developers.cloudflare.com/turnstile/plans/)、[サーバー側検証](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。
- 登録・ログイン・VM起動にはサーバー側の回数制限を組み合わせる。特にログインはアカウントと接続元の両方を考慮する。制限値と、ログイン失敗時に追加のBot検証を要求する条件は未決定。参照：[OWASP認証ガイド](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#protect-against-automated-attacks)。

回数制限値を運営設定として管理し、運営開始後も調整できるようにする案を検討する。

## 終了・再接続

以下は確定した仕様（2026-10-28）。

- 利用時間は、調査端末が操作可能になった時点から計測する。
- 利用期限が切れた場合、またはユーザーが手動終了・明示的なログアウトをした場合は、調査環境を削除する。
- 明示的なログアウト時は、セッションを無効化し、接続済みの調査端末との接続を切る。
- AWS側の予算制御が発動した場合は、プレイ中を含む稼働中の調査環境を強制終了する。ノートの保存済みデータは保持する。
- ページを閉じた後も、利用期限までは同じ調査環境へ再接続できる。
- 削除後に再度起動した調査環境は初期状態から始まる。ノートの保存済みデータは引き継ぐ。

画面に残り時間と延長・手動終了ボタンを表示すること、およびVM内のファイルが削除されることを終了前に案内することは、画面設計の案として扱う。

## 実装前に確認する追加候補

| 項目 | 仕様案 |
| --- | --- |
| 認証・認可 | 未ログインでのノート・VM利用を拒否し、画面だけでなくAPIとVM接続時にも利用者を確認する。 |
| VMの所有者 | 他のユーザーのVMに接続したり、延長・終了したりできない。 |
| 環境の隔離 | 他のユーザーの調査環境や、管理用API・DBへ調査端末から接続できない。 |
| 重複起動 | 1ユーザーにつき同時に1環境までとし、起動操作の連打でも環境を重複作成しない。 |
| 状態表示 | 起動中・利用可能・削除中・起動失敗を表示する。 |
| ノートの独立利用 | VMが起動していなくても、ノートの閲覧・回答・メモ編集を利用できる。 |
